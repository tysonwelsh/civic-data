## 4. Structured-data invariants

- **Roll size ≤ roster.** Council named-roll size distribution `{1:4, 3:5, 4:27, 5:138, 6:226}` —
  **max 6** (5 districts + voting Mayor), never exceeded. PC `MAX_ROLL=7` respected.
- **No member votes twice on one motion** — verified except the 10 documented PC dup rows (§5),
  which are identical (member,vote) repeats, not Aye+Nay contradictions.
- **Every voter name resolves** to the observed roster (10 council + 12 PC members;
  `SURNAME_ALIASES` folds Peterson→Petersen, Vilchinski→Vilchinsky, Gibbon→Gibbons, Bank→Banks).
- **Dates parse, in range, match filenames** — validate_city `d.index` PASS both bodies; no future
  meeting dates in the vote data (the 2026-06/07 PMN notices the probe surfaces are agenda-only,
  correctly absent from the index).
- **Vote vocabulary CLEAN** — distinct `vote` values: Council {Aye 2156, blank 302, Nay 16,
  Recuse 1}; PC {Aye 524, blank 71, Nay 11, Abstain 2, Recuse 2}. **Zero `Yes`/`No`** in either
  file — the Yes→Aye normalization is complete.
- **Contested spot-checks** (§3 #6,7,9,11) all match tally + attribution.

## 5. Duplicate sweep (the flagged item)

Duplicate `(source,motion_no,member)` keys with a named member:
- **meeting_minutes: 0.**
- **planning_commission: 10** — all member **Layton**, across six 2022 PC meetings:
  `934073` (m1,m2,m3), `870741` (m1,m2,m3,m4), `934075` (m1), `934057` (m1), `934053` (m1).

Cause: an early-2022 full-name PC roll printed Layton's name twice; the extractor emitted the row
twice. **Impact: none on outcomes or the db** — the db's `vote(motion_id,person_id)` UNIQUE
collapses them (2,712 CSV named rows → 2,702 db votes, delta +10 fully accounted). Same class as
the Midvale dupe. **Fix (deferred, low):** dedup identical (member,vote) within a motion in the PC
extractor, re-extract `--force`, rebuild derived. Queued in root `TODO.md`.
