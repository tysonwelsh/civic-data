# planning_commission/ — Millcreek Planning Commission vote pipeline

Millcreek runs its **OWN Planning Commission** (it does **not** rely on Salt Lake County
planning) — a full land-use body stood up after incorporation, with published minutes on the
same CivicPlus AgendaCenter portal, **2017-02 → 2026-05**. `body = "PlanningCommission"` and
`title = "Planning Commission"` on every row.

## What's here
- `minutes/<year>/<week-Monday>/<date>_<slug>.md` — **149** PC minutes files. The subdir is
  the **week-Monday** (PC meets **Wednesday**, 5 p.m.; the folder keys on that week's Monday).
  Indexed in `minutes_index.csv` (8-col standard); `source` = `civicplus` for every file;
  `format` = `pdf-text` (113) or `ocr` (36). The slug appends the docid only when a date
  carries >1 distinct meeting.
- `raw/<year>/<date>_pc_<docid>.pdf` — the retained source PDFs (never modified) + a
  `_download.log`.
- `minutes_unrecovered.csv` — **13** PC meetings that exist but whose minutes were never posted
  / are unusable — logged, never stubbed.
- `_pc_links.json` — the authoritative `[year, MMDDYYYY, docid, label]` harvest manifest that
  drives `convert.py` (see "Run").
- `convert.py` — retained-PDF → markdown converter (resumable + parallel; `pdftotext -layout`,
  `pdftoppm`+`tesseract` OCR fallback for image-only scans; rebuilds `minutes_index.csv`; runs
  the duplicate-body-hash + date-in-body decoy checks). **No vote extraction.**
- `extract_votes.py` — the PURE deterministic vote parser (no LLM, no network; resumable).
- `votes/<year>/<week>/<file>.json` — one structured JSON per meeting (the resumable
  intermediate; `all_votes.csv` is rebuilt from these).
- `votes/_validation_report.txt` — integrity checks + roster + recommendation/final split +
  contested list (regenerated by `validate_votes.py`).
- `all_votes.csv` — long format, one row per commissioner-vote (or one placeholder per
  tally-only motion), 13-col standard.
- `roster.csv` — the 21 observed commissioners with first/last-seen + meeting counts.

## Run
```
python3 convert.py           # (only when raw/ or _pc_links.json changes) rebuilds md + index
python3 extract_votes.py     # writes votes/*.json then rebuilds all_votes.csv + roster.csv
python3 validate_votes.py    # writes votes/_validation_report.txt
```
`all_votes.csv` is valid RFC-4180 — read it with a real CSV parser, NOT `awk -F,`.

## The OCR caveat — same garble as council
The AgendaCenter PDFs are scanned / bad-text-layer (`Coinmission`, `Plaru'ier`, `01son`), so
`format=pdf-text` means "had a usable text layer," **not** "born-digital clean." The parser
**fuzzy-matches** each garbled surname against the 21-name roster and leaves an unrecoverable
name **BLANK** rather than guessing. Verification confirmed **no OCR-invented commissioner
names** — every distinct named voter is a real commissioner in `roster.csv`.

## Named commissioner roll calls + tally-only unanimous
The PC names each commissioner's vote by name (best-case format), e.g.
*"Chair LaMar called for the vote. Chair LaMar voted yes, Commissioner Reid voted yes, … and
Commissioner Wright voted yes. The motion passed unanimously."* Dissent/abstain/recuse are
named (*"Commissioner LaMar voted no"* / *"Commissioner Larsen abstained"* / recused). A
**tally-only** verdict (*"voted unanimous in favor"* / *"The motion passed unanimously"* with
no per-member names) is recorded `names_recorded:false`, empty member list, and the `result`
carries the qualitative "(unanimous)" — **no numeric split or per-member attribution is
invented.** A motion that "failed due to lack of a second" never came to a vote → skipped.

## Recommendation vs final action (the PC's two motion stages)
Each PC motion is tagged as a **recommendation to the City Council** (175) or a PC **final
action** (325) — or procedural (259). The recommendation form uses explicit referral language:
*"Commissioner Reid moved that the Planning Commission recommend to the City Council…"*, and
minutes often cross-reference the council's later action (*"Council voted 5-0 on May 5 to
recommend approval of the rezone request"*). This is the strong PC→Council linkage the `db/`
`referral` layer reconstructs.

## Case numbers — Millcreek's exact land-use key
The PC cites Utah planning **case numbers** — `CU`/`ZM`/`ZT`/`SD`/`GP`/`EX`/`SV`/`PUD`… in the
format `<PREFIX>-<YY>-<NNN>` (e.g. `ZM-21-001`, `CU-17-004`) — on most land-use motions. These
are the exact key the db groups applications by and the strongest cross-body referral signal
(Millcreek's council occasionally cites the same case number verbatim, so the bridge is
genuinely two-sided — see `../db/SCHEMA.md`). `motion_type` uses a PC land-use taxonomy
(Conditional Use, Subdivision, Rezone, Zone Text Amendment, General Plan Amendment, Exception,
Street Vacation, Planned Unit Development, Other Land-Use, + Procedural/Administrative,
Ordinance, Appointment); `result`/tally are verbatim, normalized fields live in `motions_std.csv`.

## Decoy-trap avoidance + coverage
`convert.py` computes a normalized body-hash per file (duplicate-doc / mis-upload check) and a
date-in-body check (guards a wrong-date upload). The **13 unrecovered** PC meetings are logged
in `minutes_unrecovered.csv` with reasons and never stubbed. Coverage starts **2017-02-15** —
the PC's first meeting after incorporation; there is no earlier record to recover.
