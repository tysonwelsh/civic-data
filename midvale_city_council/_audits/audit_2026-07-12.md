# Midvale City — independent data-quality audit

**Date:** 2026-07-12  ·  **Scope:** newly-built `midvale_city_council/` (both bodies, all years, all derived layers)  ·  **Method:** `audit-city-data` skill (baseline screen → source ground-truth → redundancy reconciliation → completeness). Read-only; no data modified.

## Verdict: **FIX-FIRST** (council votes 2020–2023); everything else ships

The repo is well-built, faithfully sourced, and its derived layers reconcile exactly. The **one material defect** is in the **council vote extractor's handling of the two-column roll-call layout** used in the 2020–2023 minutes: it silently drops ~130 named roll calls to nameless "voice-vote" placeholders and, in 2 confirmed cases, **merges two voters into one and inverts a contested outcome** (recording a 3-2 Pass as a 2-2 Fail — including the record's sole mayoral tie-break, which the top-level CLAUDE.md itself documents as "passed 3-2"). This is invisible to the internal validator (it checks extracted-rows-vs-extracted-result consistency, which the merge satisfies) and was found only by ground-truthing against source. By 2024 the council switched to one-member-per-line rolls and the problem disappears. PC (single-column throughout), elections, comments, and the db all pass.

### Root cause (isolated)
Midvale **council** minutes 2020–2023 print roll calls **two members per physical line** (`Council Member Sperry  Aye    Council Member Glover  Aye`). The parser:
- **drops** such rolls to a nameless voice-vote placeholder when no "roll call / voting was as follows" trigger precedes them (the common case), **or**
- **merges** the two-column line into one garbled member (`Paul Glover Aye Council Member Quinn Sperry`) and **undercounts by one Aye**, which flips contested tallies.

PC rolls are **one-per-line** and parse correctly in every year (verified OCR 2021 + born-digital 2025). Council switched to one-per-line in **2024** (2024-06-04 = 0 two-column lines) and is clean thereafter.

### Scope of the loss (source-vs-extracted roll blocks)
| Years | Approx. named rolls lost to voice-vote |
|---|---|
| 2020–2021 (OCR) | ~100 (~50% of rolls; verified exact for 2020-03-03 = 4/4, 2020-03-24 = 7/8) |
| 2022–2023 (born-digital, two-column) | ~28/yr partial |
| 2024–2026 (one-per-line) | ~0 (clean) |

Two confirmed **outcome inversions**: `2020-03-24 m7` (3-2 Pass → 2-2 Fail) and `2020-05-05 m14` (mayor tie-break 3-2 Pass → 2-2 Fail).

## 3. Duplicate / over-max sweep

**dupe_sweep = 0 genuine over-5 / duplicated-roll motions in the entire corpus.** The "known 2025-08-19 dupe (10 rows / 5 members)" is a **false alarm**: two *distinct* same-date meetings (Regular = Consent Agenda; Truth-In-Taxation = "table item II"), each a legitimate 5-0 roll, correctly separated by `title`/`meeting_id`. It only appears as "10 rows" if you group by `(date, motion_no)` and ignore `title`. Keyed by `(date, title, body, motion_no)`: **0 over-5 council, 0 over-7 PC, 0 dup-member-within-motion.** The db stores them as two motions (separate meeting_ids). No fix needed; consider dropping the "documented duplicate" framing.

## 4. Mayor ceiling / Gettel transition

**mayor_ceiling_ok = yes.** Every ordinary council roll ≤ 5; 0 rows with a literal "Mayor" in the member field; exactly **one** genuine mayoral tie-break (Robert Hale, 2020-05-05 m14) — correctly the sole mayor vote and flagged `mayor_voted` in the JSON/validator. Caveat: that row's **result string is wrong** (`2-2 Fail`; should be `3-2 Pass`) — a casualty of the two-column merge, not a ceiling breach.

**Gettel = councilmember, not a mayor over-vote — confirmed.** Dustin Gettel votes as D5 councilmember 2020-01-07 → 2024-12-10 (roster + always inside a ≤5 roll), then appointed/elected Mayor for 2025+ (0 vote rows 2025+). Mayor sequence Hale (2020) → Stevenson (2022–24, appears only in motion-preamble text) → Gettel (2025+). No fabricated mayor rows.
