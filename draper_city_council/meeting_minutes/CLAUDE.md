# meeting_minutes/ — Draper City Council vote pipeline

## What's here
- `minutes/<year>/<week-monday>/<date>_<slug>.md` — **155** City Council minutes,
  **2020-01-14 → 2026-06-09**. Council meets **Tuesday** (1st & 3rd); the folder is keyed on that
  week's Monday. Indexed in `minutes_index.csv` (8-col standard: `date,year,title,slug,path,source,
  source_url,format`). **`source = granicus` (151) or `pmn` (4 promoted 2026-07-16); `format =
  text` for every file** — all born-digital PDFs (Granicus MinutesViewer / Utah Public Notice),
  **no OCR seam**. The 4 PMN promotions: **2021-07-20** (heals the former broken-Granicus-stub
  gap) + the **3 August Truth-in-Taxation specials Granicus never listed** (2022-08-24,
  2024-08-14, 2025-08-13 — Wednesday specials; the 2025 doc's header prints TUESDAY, a preserved
  clerk typo). Meetings that exist but whose minutes were never posted / are broken on the host
  live in `minutes_unrecovered.csv`, never as stub rows.
- `raw/` — retained source PDFs (never modified).
- `extract_votes.py` — the deterministic parser (resumable). Run it to regenerate everything below.
- `votes/<year>/<week>/<date>_*.json` — one structured JSON per meeting (the resumable intermediate;
  `all_votes.csv` is rebuilt from these). `votes/_validation_report.txt` = integrity checks + per-year
  roster + tally flags (regenerated by `validate_votes.py`).
- `roster.csv` — 7 members observed with first/last vote + count.
- `all_votes.csv` — long format, **one row per member-vote** (or one placeholder row per tally-only
  motion), the 13-column standard **+ a documented trailing 14th `provenance` column** (2026-07-16:
  `minutes` = audited Granicus doc, `pmn_minutes` = PMN-recovered promoted doc — 43 rows). Valid
  RFC-4180 — motion text contains commas/quotes, so **read it with a real CSV parser, NOT `awk -F,`**.

## Run
```
python3 extract_votes.py     # writes votes/*.json then rebuilds all_votes.csv
python3 validate_votes.py    # writes votes/_validation_report.txt
```

## The Recap-vs-Minutes trap (the acquisition rule)
Granicus offers, for recent meetings, BOTH a tally-only 1-page **Recap** and the full **Minutes**
behind a JS document selector. **Always keep the full Minutes and drop the Recap.** The full Minutes
carry named `Yes / No / Absent` roll-call grids (what the extractor needs); the Recap has only a
tally. The build resolved every case to the full Minutes; a meeting for which only a Recap has been
posted so far (2026-07-07) is **withheld and logged `recap_only_pending`** in
`minutes_unrecovered.csv` — never stubbed with the Recap. When refreshing, re-check that a new
recent date resolved to Minutes, not Recap (`VERIFICATION.md` §4).

## Vote grammar — named roll-call grids + tally-only motions
Draper minutes print a **named `Yes/No/Absent` grid** per motion (each of the 5 members on its own
line) — a clean full roll call the parser reads directly. Adjournments and some voice votes are
**tally-only** (`result` like `Unanimous (voice/tally-only)`) → one placeholder row with blank
member/vote. Some **2020–2021 narrative motions name only the in-favor side** ("Councilmembers
Green, Roberts, Lowry, Lowery, and Vawdrey voting in favor") — captured faithfully; a member absent
from such a list is a recording limit, never Present-filled. `result` and `motion_type` are
**verbatim as printed**; normalized outcome/tallies/type live **alongside** in `motions_std.csv`.

## The single mayoral vote — a genuine tie-break (2024-10-15)
`Mayor Troy K. Walker` appears in **exactly one** vote row in the corpus: **2024-10-15, motion 3,
Ordinance #1625** (`3-2 Pass`). The five members split **2 Aye (Green, Roberts) / 2 Nay (Johnson,
T. Lowery) / 1 Recuse (F. Lowry)** and Walker cast the deciding **Aye**. Stored as an ordinary `Aye`
row (no special note field, unlike Park City). This is the extractor's key structural fact — the
Mayor is non-voting on every other motion.
