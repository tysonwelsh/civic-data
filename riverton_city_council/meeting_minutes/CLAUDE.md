# meeting_minutes/ — Riverton City Council vote pipeline

## What's here
- `minutes/<year>/<week-monday>/<date>_city-council.md` — **128** City Council minutes,
  2020-02-18 → 2026-06-02. Council meets **1st & 3rd Tuesday**; the folder is keyed on that
  week's Monday. Each meeting-day is **one combined doc** (Informal Meeting → Work Session →
  Regular Meeting). Indexed in `minutes_index.csv` (13-col standard; `source=pmn` and
  `format=text` for every file — all born-digital, **no OCR**). **0 unrecovered meetings** (the
  Utah PMN mirror is complete for the 2020 floor).
- `raw/<date>_*.pdf` — the retained source PDFs (never modified).
- `extract_votes.py` — the deterministic parser (no network; resumable). Run it to regenerate
  everything below.
- `votes/<year>/<week>/<date>_*.json` — one structured JSON per meeting (the resumable
  intermediate; `all_votes.csv` is rebuilt from these).
- `votes/_validation_report.txt` — integrity checks, per-year roster, mayor-vote flags, tally
  mismatches, contested-vote list (regenerated by `validate_votes.py`).
- `roster.csv` — councilmembers observed from named votes: `member, role, first_seen, last_seen,
  vote_rows, mayor_tiebreaks`.
- `all_votes.csv` — long format, **one row per member-vote** (or one placeholder row per
  tally-only motion), schema:
  `date,year,title,body,motion_no,motion,motion_type,result,mover,seconder,member,vote,source`
  **+ a documented trailing `provenance` column** (14th): `minutes` = audited series,
  `pmn_minutes` = the 5 recovered meetings merged from `../pmn_backfill/` (below).
- `extract_backfill_votes.py` — merges the **5 recovered council meetings** in
  `../pmn_backfill/` (2020-01-07, 2020-01-21, 2020-02-04 — Word-era files predating the
  audited series; 2023-09-05, 2023-11-07 — Granicus-only, PMN never carried their minutes)
  into `all_votes.csv`, reusing this dataset's own parser and tagging
  `provenance=pmn_minutes` (promoted 2026-07-16). Their `source` points at
  `pmn_backfill/text/…` — they are NOT in `minutes_index.csv`/`minutes/` and do not feed
  `roster.csv` first/last-seen (2020-03-17 there = first audited named vote). Three bounded
  parse tolerances (missing name-vote hyphens verified absent in the raw .docx; one
  "Roll Call vote." introducer; one un-anchored "made a SUBSTITUTE motion") are documented
  in the script docstring — the stored raw/text files stay verbatim.

## Run
```
python3 extract_votes.py            # writes votes/*.json then rebuilds all_votes.csv
python3 extract_backfill_votes.py   # re-merges the 5 pmn_backfill meetings (provenance col)
python3 validate_votes.py           # writes votes/_validation_report.txt
```
`all_votes.csv` is valid RFC-4180 (motion text contains commas/quotes — read it with a real CSV
parser, NOT `awk -F,`).

## Vote grammar — named roll calls, some tally-only
Riverton's Council clerk usually prints a **named roll call** (`"the vote was as follows:
Buroker-Yes, McCay-Yes, …"`), so most motions carry per-member `Aye`/`Nay` rows. Some motions
record only a **tally / narrative outcome** (`"passed unanimously"` with no names) → one
placeholder row, `member`/`vote` blank (134 motions). A blank member list is the source style,
not an extraction miss. Mover + seconder are captured on nearly every motion.

## Council composition / the Mayor does NOT vote (except a real tie-break) — Park City model
Six-member council form: **5 district members** + a separately-elected **Mayor** who **presides
but does NOT vote on ordinary motions** (max ordinary tally = **5**). The Mayor votes only to
break a tie (or on manager hiring/firing / amending mayoral powers). Roster observed

archive — clean born-digital text PDFs (`source=pmn`, `format=text`). The city's Revize CMS lists
dates only. See `../recon.md` / `../SOURCES.md`.
