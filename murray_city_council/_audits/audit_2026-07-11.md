# Murray City — independent data-quality audit

**Date:** 2026-07-11 · **Auditor:** independent audit pass (read-only; no canonical file mutated)
**Scope:** newly built `murray_city_council/` — council + PC minutes/votes, elections, geo,
comments, derived db/weeks. Methodology: `audit-city-data` skill (statistical screen →
ground-truth → redundant-fact reconciliation → derived-layer checks → completeness).

## Verdict: **FIX-FIRST (light)** — ship-quality repo with ONE confirmed, bounded, currently-mischaracterized data-loss defect.

The extraction pipeline is faithful and internally consistent across every dimension checked
(vote invariants clean, db reconciles to the row, elections reconcile 3 ways, dates
consistent, honorifics resolved, mayor-non-voting structurally correct). The single defect is
**5 scanned image-only PDFs that produced empty (header-only) markdown**, silently dropping
their votes — and `VERIFICATION.md` calls them "legitimately vote-free," which is not true
(OCR proves votes exist). Fix the 5 (OCR/vision or log as unrecovered) and correct the doc,
then ship.

## 1. Statistical corpus screen — **issues (1 real, bounded)**

`weird_char_outlier` 2/132; `stub<200B` 1/132.
- **2 weird-char files (2020-08-04, 2020-10-20): COSMETIC — CONFIRMED benign.** Garble is
  confined to embedded decorative-graphic regions (a "Chair Statement" graphic block and an
  embedded flyer; defective font cmap → garbled Latin-Extended/PUA glyphs, e.g. lines 521–529
  of 2020-08-04). **Vote blocks are fully clean** (`Ayes:/Nays:/Motion passed N-M` all
  readable) and the garble **does not reach extracted data** — verified all rows for both
  meetings match source (incl. the 4-1 Turner-Nay and 4-0-1-Abstain motions). Matches the
  task's known cosmetic-garble note.
- Per-year `split_word` medians 2023=0.38, 2026=0.54/1k are **not** statistical outliers
  (0/132 flagged) — trivially low absolute rates from the tabular "Council Roll Call Vote:"
  era; benign.
- `repeated_line`/`ends_mid` advisories (69/132, 94/132) are page-header/legal-layout noise —
  benign.

**PC** (61 files) — `dict_ratio` 0.79–0.80 stable; `split_word_outlier` 0/61; `stub<200B`
4/61; `hyphen_breaks` 1/61 (benign).

## RANKED FIX LIST

### 1. [HIGH-value / MEDIUM-severity] 5 scanned image-only PDFs → empty markdown → lost votes; mischaracterized as "vote-free"
- **What:** These 5 "minutes" are Adobe-PDF-Scan image-only PDFs (jpeg/ccitt, no text layer);
  `pdftotext` yields ~5–8 chars, so the markdown is header-only (<210B) and no votes were
  extracted:
  - `meeting_minutes/minutes/2022/2022-06-20/2022-06-21_city-council-meeting.md` (raw
    `…adid6173.pdf`, 6 pp) — **OCR confirms ≥2 roll-call votes (both "Motion passed 5-0")
    currently absent from `all_votes.csv`.**
  - `planning_commission/minutes/2020/2019-12-30/2020-01-02_…md` (raw `…adid4919.pdf`, 6 pp)
  - `planning_commission/minutes/2020/2020-01-13/2020-01-16_…md` (raw `…adid4920.pdf`, 8 pp)
  - `planning_commission/minutes/2020/2020-02-03/2020-02-06_…md` (raw `…adid4936.pdf`, 5 pp)
  - `planning_commission/minutes/2020/2020-02-17/2020-02-20_…md` (raw `…adid4937.pdf`, 10 pp)
- **Why it matters:** real data loss (votes + hearings), and `VERIFICATION.md` §(a) labels the
  "5 council / 4 PC zero-motion docs" as "legitimately vote-free meetings (canvass / study /
  procedural-only)" — false for these 5. (Note: the *other* 3 council zero-motion docs —
  2024-02-20, 2024-03-05, 2026-02-17 — DO have real text and are genuinely vote-free.)
- **Fix:** OCR/vision the retained `raw/` PDFs (tesseract is available; scans OCR cleanly) →
  re-convert → re-run each dataset's `extract_votes.py` + `validate_votes.py` → rebuild
  db/motions_std/weeks. If any prove genuinely motion-free after OCR, keep the text anyway.
  Then correct `VERIFICATION.md` §(a) to split "scanned-image, text-unrecovered" from
  "genuinely vote-free."

### 2. [LOW] Provenance drift — scanned PDFs labeled `pdf-text`
- `SOURCES.md` states "How the text was obtained: pdf-text (132)" / "pdf-text (61)" and
  `minutes_index.csv` `format=pdf-text` for all rows, but the 5 files in fix #1 are
  scanned-image (no text layer). Reclassify those 5 `format` values (e.g. `pdf-scan` /
  `ocr` once recovered) so the provenance is honest.

### 3. [LOW] Doc drift — referenced files that don't exist
- `CLAUDE.md` and `README.md` reference **`db/SCHEMA.md`** ("read `db/SCHEMA.md` first" /
  "see `db/SCHEMA.md`") — **missing**.
- `CLAUDE.md` claims "Each subfolder has its own CLAUDE.md/SCHEMA.md with build details," but
  `meeting_minutes/`, `planning_commission/`, and `db/` have **no** CLAUDE.md/SCHEMA.md (only
  `election_results/` and `geo/` do).
- **Fix:** create the missing schema/subfolder docs or drop the references.

### 4. [INFO — not a defect] 3 tally-vs-named soft mismatches
- Council `2022-02-01` m2 (source prints 5-0, lists 4 Ayes), Council `2025-06-17` m2 (failed,
  clerk prints nays-first "3-2"), PC `2022-04-07` m5 (7 `__A__` marks vs printed "6-0"). All
  are verbatim captures of source clerk inconsistencies, already soft-flagged in the
  validation reports. **Leave as-is** (result strings are city-faithful); no action.
